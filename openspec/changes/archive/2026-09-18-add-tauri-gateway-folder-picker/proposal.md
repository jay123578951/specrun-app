## Why

打包出來的桌面 App **進不了門**。側欄的「加入專案」按下去只會跳一句「Could not open the folder picker.」，而規格明訂原生資料夾選擇是加入專案的**唯一入口**、不得提供手打或貼上路徑的替代輸入（`project-management` 的「加入專案」）。一個剛裝好的 `.app`，只要不是剛好從某個專案目錄啟動的，清單就是空的，而且畫面上沒有第二條路可走。

原因是這條路還沿用 web 形態那一份，去打 `/api/pick-folder`——而 `.app` 裡沒有本地 API server。開發時看不出來：vite 把 `/api` 轉給 3210，所以桌面開發通路一直是通的（實測 `/api/health` 經 5173 與直打 3210 皆有回應）。這是 T4b 兩條剩餘路徑裡影響最大的一條：另一條（開啟檔案所在位置）在桌面形態已經誠實地呈現為禁用並說明原因，這一條卻是點下去才失敗。

## What Changes

- 原生資料夾選擇 SHALL 改由**當前執行形態自行持有**：桌面形態走外殼自己的選擇通道，web 形態維持現狀走本地 API server。gateway 介面不變，畫面端零改動。
- 「具不具備原生選資料夾能力」的判定 SHALL 由當前執行形態負責。規格原本寫成「由伺服端依其執行平台判定」，該措辭在桌面形態已不成立——桌面形態沒有伺服端可問。同一句話在 `app-settings` 與 `openspec-gateway` 早已是形態中立的寫法，本張把 `project-management` 對齊過去。
- 原生資料夾選擇視窗 SHALL 附著於 App 主視窗呈現，開啟期間主視窗 SHALL 不接受輸入。這條把「連按兩次加入專案會不會疊開兩個選擇視窗」從實作巧合變成規格保證——附著期間那顆按鈕點不到，重複開啟不可能發生。
- 選定資料夾後的處理 SHALL 完全不變：路徑正規化、`openspec/` 驗證、驗證失敗以 toast 提示且不加入清單、重複專案切換過去、加入即切換並回到 Changes 頁。本張換的只是「那個視窗由誰開」。
- 選定資料夾的動作本身 MUST NOT 擴大 App 對該資料夾的讀取權限。驗證前授予的權限 SHALL 限於列出該資料夾的內容，整棵樹的讀取 SHALL 於驗證通過後才授予。桌面外殼的權限清單只能加不能減，驗證不通過的資料夾撤不回來——挑錯一次不該換來那個資料夾裡每個檔案的讀取權。

**非目標**（留給後續 change）：

- **開啟檔案所在位置**與 **artifact 內容裡的外部連結**——兩者共用同一個外殼通道，併為 T4b 的後半。本張完成後，Settings 的「開啟所在位置」仍是禁用並說明原因，artifact 裡的外部連結仍點了沒反應（已實測：桌面視窗沒有掛新視窗處理器，WKWebView 直接放棄該次導覽，不開瀏覽器也不報錯）。
- **web 形態與本地 API server 的整批下線**：早期規劃（T2、T4 的 design）曾把「web 那側整批刪除」寫進 T4 的預期，本張不做，也不預設它一定會發生。桌面開發通路目前仍併跑本地 API server。
- **`desktop-gateway.ts` 沿用 web 形態那一份的那一行不拿掉**：開啟所在位置還靠它，後半才拿掉。
- **web 形態的資料夾選擇實作不動**：`server/api/pick-folder.post.ts` 與 `server/utils/folder-picker.ts` 原樣留著。
- **選擇視窗的起始位置不設**：沿用現況，由作業系統決定停在哪。

## Capabilities

### New Capabilities

（無——本 change 不引入新的能力，只更換既有能力的持有者與執行形態。）

### Modified Capabilities

- `project-management`：「加入專案」的能力判定由「伺服端依其執行平台判定」改為由當前執行形態判定；補上選擇視窗附著於主視窗、開啟期間主視窗不接受輸入；補上選定動作本身不得擴大讀取權限、驗證前只給列出內容的權限。
- `desktop-shell`：「桌面視窗形態啟動」的自持範圍擴及加入專案的資料夾選擇；過渡期間仍經本地 API server 的只剩開啟檔案所在位置。另補一條驗收情境：打包形態下加得了專案。

## Impact

- **搬移來源**：`server/api/pick-folder.post.ts` 與 `server/utils/folder-picker.ts`。要保留的是結果的分類方式（選到了／取消／開不起來／平台不支援）；換掉的是開視窗的機制——現行以 `osascript` 執行 AppleScript 的 `choose folder`，因此只在 macOS 成立，且取消與否得靠錯誤訊息的關鍵字去猜。
- **資料入口**：`OpenSpecGateway` 的 `pickFolder` 在桌面形態改由新實作承接。`PickFolderOutcome` 的五個狀態全部保留——桌面形態不會再回「平台不支援」與「已有視窗開著」，但 web 形態仍會。`src/stores/projects.ts` 的 `startAdd` 零改動。
- **新增桌面模組**：一份桌面形態的資料夾選擇模組，以及外殼通道薄層（`src/api/desktop/shell.ts`）新增一個對應的出口。
- **外殼與權限**：`src-tauri` 新增一項相依（Tauri 官方的對話框外掛）並於啟動時註冊；`src-tauri/src/lib.rs` 新增一個自有指令，比照既有的外部指令執行、路徑授權等指令的寫法。webview 端的權限清單**不新增對話框相關項目**——前端呼叫的是這個自有指令，不是外掛自己的指令。
- **相依套件**：JS 端不新增套件；沿用既有慣例，由前端直接呼叫外殼指令。
- **不動**：`src/api/desktop/projects.ts` 的加入流程（正規化、驗證、兩階段授權、寫入清單的順序）、`src/api/web-gateway.ts`、`src/stores/projects.ts`、所有畫面元件。
- **可觀察的中間態**：本 change 完成後，打包的 App **加得了專案**，這是它第一次真的能獨立使用。仍不能用的是開啟檔案所在位置（按鈕禁用並說明原因）與 artifact 裡的外部連結（點了沒反應）。
