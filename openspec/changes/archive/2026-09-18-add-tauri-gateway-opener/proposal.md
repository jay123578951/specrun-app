## Why

桌面形態還有兩件事交不出去，兩件都是「把東西丟給作業系統開」：

- **開啟檔案所在位置**：Settings 診斷區的設定檔位置與目前專案路徑各帶一顆按鈕。桌面形態下兩顆都是禁用，說明寫著「這個形態還沒有這個通道」。這句話是誠實的，但它描述的是一個已經沒有理由繼續存在的狀態——T4a 已經用同一套手法把「檔案變動通知」從可能未知收斂成永遠答得出是或否。
- **artifact 內容裡的外部連結**：渲染出來的 `<a target="_blank">` 在瀏覽器裡會開新分頁，在桌面視窗裡什麼都不會發生。`artifact-view` 的「連結行為」已明訂外部 URL 連結 SHALL 於系統瀏覽器開啟，桌面形態目前不符合這一條。而且它的失敗是無聲的：點下去沒反應，跟連結壞掉、跟 App 當掉，使用者分不出來。

兩者共用同一個外殼通道（同一個外掛的兩個指令、同一份權限設定），拆成兩張要重複改兩次 `Cargo.toml` 與權限清單，所以併為一張。

這也是桌面形態最後一條還在借用 web 形態的路。`desktopGateway` 目前覆寫了資料入口 22 個方法中的 21 個，唯一沿用 web 那一份的就是開啟所在位置。本張完成後那一行沿用可以拿掉，桌面形態的資料入口 100% 由自己持有。

## What Changes

- **開啟檔案所在位置 SHALL 改由當前執行形態自持**：桌面形態走外殼自己的通道，web 形態維持現狀走本地 API server。畫面端零改動——按鈕、圖示、鍵盤行為、說明文字的三條取得路徑全部不變，變的只有它從禁用變成可按。
- **「能不能開啟所在位置」SHALL 在任何執行形態都回報明確的是或否，MUST NOT 回報未知**。這一條比照 T4a 對「檔案變動通知」的收斂：本張之後，這個問題在每個形態都問得到答案，「未知」沒有任何來源，留著它等於留一段永遠走不到的畫面分支。
  - 連帶：`app-settings` 的「開啟所在位置的平台降級」從四種禁用成因收斂為三種（診斷還沒回來／這個平台辦不到／那一項沒有路徑可開），「這個形態尚無通道可問」那一種連同它的措辭一併移除。
- **新增「把外部網址交給系統開啟」的通道**：這是資料入口新增的一個方法。結果為成功或失敗兩態，MUST NOT 有「此環境不支援」一態——web 形態一定開得了新分頁，桌面形態具備外殼通道，沒有形態答得出不支援。
- **外部連結的點擊 SHALL 由畫面這一側接住**，交給上述通道處理，兩個執行形態走同一條路。點擊 SHALL NOT 因鍵盤修飾鍵而改走瀏覽器原生行為——形態之間的行為差異不得由使用者按了什麼鍵決定。
  - 使用者感受得到的代價：在瀏覽器裡跑的開發通路，Cmd／Ctrl＋點從背景分頁變成前景分頁。桌面形態是交付形態、瀏覽器形態是開發通路，不為後者的次要手勢在元件裡開分支。
- **開啟外部網址失敗時 SHALL 以非阻斷提示告知**，MUST NOT 靜默。靜默等於維持現在這個毛病：使用者無從分辨「沒開起來」與「這個連結本來就不能點」。
- **可交給外殼開啟的網址範圍 SHALL 限於 http、https、mailto**，其餘一律在到達外殼之前就擋下。這與現行渲染層對「什麼算外部連結」的判定完全一致，本張不放寬也不收窄。
- **`desktop-gateway.ts` 沿用 web 形態那一份的那一行拿掉**：所有方法都自己實作，不再有繼承來的方法。

**非目標**（維持現況，或留給後續）：

- **相對路徑連結仍不可點**：`artifact` 互跳與「用編輯器開啟」是刻意延後的範圍，維持現行的灰字加虛線底線、點了不做任何事。本張不碰它。
- **App 自己畫的地方不納入**：範圍只到 artifact 內容裡的連結。App 的介面目前一個 `<a>` 都沒有，沒有第二處要接。
- **`/api/reveal` 與 `server/utils/reveal.ts` 原樣留著**：web 形態沒有別的通道可走。
- **`open_path`（用預設程式開這個檔）不接**：那是「用編輯器開啟」的材料，屬觀察項，本張只接 reveal 與 open url 兩個指令。
- **web 形態與本地 API server 的整批下線**：T4b 已定案不做，本張沿用。桌面開發通路仍併跑本地 API server。
- **連結的外觀不改**：hover 底線變色、按下、鍵盤聚焦框那一組維持原樣。行為改變不需要外觀跟著改。

**已知會留下的粗糙處**（刻意不處理）：在瀏覽器裡跑的開發通路點 mailto 連結時，可能留下一個空白分頁。那是瀏覽器開新分頁對 mailto 的既有行為，不是本張引入的；artifact 內容裡出現 mailto 的機率極低（本專案目前 0 筆），痛感真實出現再處理。

## Capabilities

### New Capabilities

（無——本 change 不引入新的能力區塊，只更換既有能力的持有者，並在既有的資料入口能力上新增一個通道。）

### Modified Capabilities

- `openspec-gateway`：「環境診斷通道」的「開啟檔案所在位置是否可用」一項，由「尚無通道可問時回報未知」收斂為任何形態都回報明確的是或否；另新增「開啟外部網址通道」一條需求（兩態結果、網址範圍限於 http／https／mailto）。收斂掉的是一整條 scenario，而規格的改寫方式不容許在原地刪 scenario，因此該需求走「整條移除＋改名重立」：`環境診斷通道` → `環境診斷與開啟位置通道`，仍成立的內容原文搬過去（先例：`drag-to-switch-change-state` 的「群組與排序」）。
- `artifact-view`：「連結行為」補上外部連結的點擊由當前執行形態開啟、不因修飾鍵改道、開啟失敗以非阻斷提示告知、App 畫面與捲動位置不變。這一條是就地改寫，沒有 scenario 被拿掉。
- `app-settings`：禁用成因由四種收斂為三種，移除「這個形態尚無通道可問」。同樣因為要拿掉一整條 scenario 而走移除＋改名重立：`開啟所在位置的平台降級` → `開啟所在位置不可用時的呈現`（舊名也已名實不符——三種成因裡只有一種與平台有關）。
- `desktop-shell`：「桌面視窗形態啟動」的自持範圍擴及開啟檔案所在位置與開啟外部網址；過渡期間仍經本地 API server 的路徑歸零。另補驗收情境：打包形態下開得了檔案所在位置、點得動 artifact 裡的外部連結。

## Impact

- **搬移來源**：`server/utils/reveal.ts`（以 `open -R` 在 Finder 選取項目，因此只在 macOS 成立）。要保留的是結果的分類方式（開了／這個平台辦不到／失敗）；換掉的是開啟的機制。桌面形態的通道三個平台都有實作，所以它永遠答「可以」，非 macOS 只會落在「失敗」而不是「辦不到」。
- **資料入口**：`OpenSpecGateway` 新增一個開啟外部網址的方法（兩形態各一份實作）；`revealPath` 在桌面形態改由新實作承接。`RevealOutcome` 的三態全部保留——桌面形態不會再回「這個平台辦不到」，但 web 形態在非 macOS 仍會。`EnvironmentDiagnostics` 的「能不能開啟所在位置」一項由三態（是／否／未知）收斂為兩態。
- **新增桌面模組**：一份桌面形態的模組同時放兩條路，以及外殼通道薄層（`src/api/desktop/shell.ts`）新增兩個對應的出口。
- **畫面端**：`MarkdownView.vue` 的點擊委派要能在唯讀模式下也運作——它目前在開頭就因為「不是可勾選模式」整段退出，只服務 tasks 勾選。三個看內容的地方共用這個元件：change 詳情、Specs 全文、已歸檔詳情。`src/markdown/render.ts` 的連結處理保留 `target="_blank"` 與 `rel` 不拿掉——接住那段若失效，留著它是開新分頁、App 狀態還在；拿掉會在同一個畫面導航走，整個 App 被換掉。
- **`SettingsModal.vue`**：移除「這個形態還沒有這個通道」那一句說明與它的分支，其餘三種成因的措辭不動。
- **外殼與權限**：`src-tauri` 新增一項相依（Tauri 官方負責把東西交給作業系統開的外掛）並於啟動時註冊；`src-tauri/capabilities/default.json` 新增兩項權限——一項涵蓋 mailto／tel／https／http 的預設網址集，一項是在檔案管理器中選取項目。**與 T4b 不同，本張預期不需要自寫 Rust 包裝**：T4b 之所以自己包，是因為資料夾對話框外掛的前端指令會在驗證前就擴大檔案可讀範圍；這個外掛沒有同等的已知行為。這一點在動手時要實際確認，確認結果若相反則退回 T4b 的做法。
- **相依套件**：JS 端不新增套件；沿用既有慣例，由前端直接呼叫外殼指令。
- **順帶收尾**（ROADMAP 在 tauriGateway 移植那一項指定的）：`src/api/index.ts` 的 `getHealth` 移除。它繞過資料入口直接打本地 API server，功能早已由環境診斷取代，目前沒有任何呼叫端。本張是 gateway 移植的最後一張，收在這裡。
- **不動**：`src/stores/settings.ts` 的 `reveal` 流程、`src/api/web-gateway.ts` 的 `revealPath`、`server/api/reveal.post.ts`、`server/utils/reveal.ts`、所有樣式。
- **可觀察的中間態**：本張完成後，打包的 App **開得了檔案所在位置、點得動 artifact 裡的外部連結**。桌面形態的資料入口至此完全不再借用 web 形態那一份。ROADMAP 的 T4 堆疊只剩 T5（發佈）。
