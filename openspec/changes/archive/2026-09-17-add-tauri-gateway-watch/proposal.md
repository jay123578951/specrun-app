## Why

T3 之後，打包出來的桌面 App 已經讀得出 change、勾得動任務、park 得動——但它的畫面是靜的。勾一個 checkbox，左邊卡片的進度數字不會跟著動；在終端機讓 AI 改完一輪 tasks.md，App 完全沒反應。兩者都要切頁再回來才更新。

原因同一個：檔案變動通知還掛在本地 API server，而 `.app` 裡沒有它。勾選的成功路徑刻意不做任何重載（T3 design D6），刷新一向交給通知——通知斷了，那個設計就露出破口。這是 M4 移轉裡最後一條影響日常手感的路，搬完之後桌面版才真的「自己會動」。

搬完還順帶清掉一筆技術債：桌面形態切換專案時補打本地 API server 的那一趟過渡呼叫，唯一的存在理由就是讓 server 上的監看跟著換目標。監看搬過來之後，本地 API server 不再需要知道目前專案是哪個，那個函式與三處呼叫一併刪除。

## What Changes

- 檔案變動通知 SHALL 改由**當前執行形態自行持有**：桌面形態走外殼的檔案監看通道，web 形態維持現狀走本地 API server 的推播。gateway 介面不變，畫面端零改動。
- 通知的「連環變動合併為一則」SHALL 由 gateway 實作端保證，MUST NOT 依賴底層監看機制自己的合併。桌面形態的監看通道即使開了延遲合併，仍是一批事件逐則往上送；不自己再合一次，一次 git 操作會變成數十趟引擎呼叫。
- 監看目標 SHALL 為解開 symlink 後的實際位置。事件回報的是實際位置，監看路徑與它對不起來時，「這則變動算不算數」的判斷會把每一則都濾掉。
- 環境診斷的「檔案變動通知是否運作」SHALL 改為表達「是否已接上」，並且在任何執行形態都 SHALL 答得出是或否，MUST NOT 再有「該形態尚無通道可問」的未知態。桌面形態的監看通道不回報中斷——接上之後收不到任何失效訊號，沿用舊語意會在監看已死時仍宣稱它在運作。
- 通知通道的自動重連與補償重載 SHALL 限縮為「會斷線的執行形態」的責任。桌面形態的通知在同一個行程內傳遞，沒有斷線這回事，補償重載沒有觸發條件。

**非目標**（留給後續 change）：

- 原生選資料夾、開啟檔案所在位置，以及 web 形態與本地 API server 的整批下線——最後一張（T4b）。本張完成後桌面開發通路仍併跑本地 API server。
- **監看範圍不擴**：仍只看目標專案的 `openspec/changes/`。Specs 頁與 Archived 頁維持「進頁重新載入、不擴充監看」（C8／C9 定案），parked 目錄的外部變動仍不觸發通知。
- **批次改檔期間不先刷新一次**：連續寫入時畫面要等批次停下來才更新，沿用現行語意。盯著 pipeline 跑的體感是另一個題目，痛感真實再開 change。
- **底層監看的延遲合併設多久**不寫入 spec：它只影響跨行程的訊息量，畫面上看不出差別。

## Capabilities

### New Capabilities

（無——本 change 不引入新的能力，只更換既有能力的持有者與執行形態。）

### Modified Capabilities

- `openspec-gateway`：「檔案變動通知」補上兩條形態中立的限制——合併的責任在 gateway 實作端、監看目標為解開 symlink 後的實際位置；「通知通道之韌性」的自動重連與補償重載限縮為會斷線的形態；「環境診斷通道」的通知欄位語意由「目前是否運作」改為「是否已接上」，並移除該欄位的未知態。
- `desktop-shell`：「桌面視窗形態啟動」的自持範圍由「設定、CLI 執行檔解析、change 與 spec 的讀取、檔案操作面」擴及檔案變動通知；過渡期間仍經本地 API server 的只剩原生對話框與開啟所在位置。另補一條：桌面形態 MUST NOT 為了讓本地 API server 跟上目前專案而回頭呼叫它。
- `app-settings`：「唯讀診斷資訊」的即時刷新項語意跟著改為「是否已接上」，且該項在任何形態都有明確的是或否。

## Impact

- **搬移來源**：`server/api/watch.get.ts` 與 `server/utils/change-watcher.ts`。合併、範圍過濾、切換後重接這三件事的規則照搬，換的是監看與事件傳遞的機制。
- **資料入口**：`OpenSpecGateway` 的 `subscribeToChanges` 在桌面形態改由新實作承接。介面不變——桌面端內部自行處理「專案換了要重接」，MUST NOT 把重接推給呼叫端。`src/App.vue` 零改動。
- **新增桌面模組**：一份桌面形態的監看模組（接上、重接、合併、取消訂閱、回報是否已接上）。範圍過濾沿用 T3 的 `src/api/desktop/paths.ts`，不另造。
- **既有桌面模組**：`src/api/desktop/projects.ts` 新增「目前專案變動」的訂閱出口，並刪除過渡同步呼叫（`syncLocalServer`、三處呼叫、等待上限常數）；`src/api/desktop/diagnostics.ts` 的通知欄位由未知改為實際狀態。
- **型別**：`EnvironmentDiagnostics` 的通知欄位由三態縮為兩態；`SettingsModal` 的診斷列不再需要為該項的未知態留分支。
- **外殼與權限**：零改動。監看與取消監看兩項權限已在清單內，底層的監看能力也已在建置設定中啟用。
- **不刪**：`server/api/watch.get.ts` 與 `server/utils/change-watcher.ts` 都留著，web 形態還要用。
- **可觀察的中間態**：本 change 完成後，打包的 App 勾完任務卡片數字會自己動、外部改檔會自動刷新、Settings 的即時刷新那一行從佔位符變成明確的是或否。仍不能用的是：以原生對話框加入專案、開啟檔案所在位置。
