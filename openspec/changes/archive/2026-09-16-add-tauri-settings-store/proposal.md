## Why

打包出來的桌面 App 現在打開是空的——`.app` 裡只有前端靜態檔，沒有本地 API server，而所有資料都得經過它。要讓桌面形態獨立運作，第一個非搬不可的是「現在是哪個專案」與「openspec 執行檔在哪」這兩個答案的持有處：四條讀取路徑（change 清單、change 詳情、spec 清單、spec 全文）每一條都得先問過它們才動得了。

這個持有處不能拆成兩半。兩個答案共用同一個設定檔，而兩邊的寫法都是讀回整份、改一欄、整份寫回去——若一半留在本地 server、一半搬到桌面外殼，兩個行程各自快取同一份檔案，後寫的會蓋掉先寫的：使用者剛加入的專案會在設定 CLI 路徑之後憑空消失。

先搬它還有一個時機上的理由。CLI 自動偵測的第二階段（借使用者 login shell 取得絕對路徑）存在的唯一理由，就是「macOS 的 App 從 Finder 點開時不繼承 shell PATH」。但這段程式至今從未在它真正要服務的環境裡執行過：開發通路下本地 server 由終端機啟動、繼承了 PATH，第一階段就命中；而打包的 App 連 server 都沒有。把它留到最後一張 change 才第一次驗證，等於把最沒把握的一條路擺在發佈前夕。

## What Changes

- 設定檔的讀寫、專案清單與目前專案狀態、CLI 執行檔解析，三者一併改由**當前執行形態自行持有**：桌面形態走外殼通道，web 形態維持現狀走本地 API。
- 桌面形態的設定檔位置 SHALL 與 web 形態相同，兩者共用同一份——同一台機器上不論用哪種形態開啟，專案清單與 CLI 設定都是同一份。
- 外殼的外部指令執行通道補上逾時上限。借 login shell 偵測會執行使用者自己的 shell 設定檔，目前的通道會一直等下去，設定檔裡有東西卡住就會讓整個 App 沒有反應。
- 外殼的靜態檔案存取範圍改指向共用的設定目錄。目前放行的是外殼預設的資料目錄，與 web 形態實際使用的目錄不是同一個。
- 環境診斷中「檔案變動通知是否運作」與「能否開啟檔案所在位置」兩項，在桌面形態尚未具備對應通道前，SHALL 明確表達為尚未可用，MUST NOT 以 web 形態的答案充數。

**非目標**（留給後續 change）：

- change 清單與詳情、spec 清單與全文的讀取面——下一張。
- tasks 勾選、park／unpark、archived 直讀——再下一張。
- 檔案變動通知、原生選資料夾、開啟檔案所在位置——最後一張。
- 原生選資料夾尚未搬移，而它是「加入專案」的唯一入口——畫面上沒有第二條貼路徑的途徑，且它仍走本地 API server。因此打包形態下按「加入專案」會失敗；打包的 App 側欄列得出的專案，來自先以開發通路加好、兩形態共用的那份設定檔。

## Capabilities

### New Capabilities

（無——本 change 不引入新的能力，只更換既有能力的持有者與執行形態。）

### Modified Capabilities

- `openspec-gateway`：「CLI 執行檔解析」目前要求解析結果由伺服端持有，改為由當前執行形態持有；「目標專案路徑解析」同理，並寫明環境變數與工作目錄兩段只在具備該通道的形態成立；「環境診斷通道」目前要求可用性判定在伺服端，同理放寬，並補上「通道尚未具備時明確表達為尚未可用」。
- `app-settings`：「開啟所在位置的平台降級」目前要求能力判定在伺服端，改為由當前執行形態判定；並補上禁用原因要能以鍵盤與輔助技術取得，不是只在指標停留時出現。診斷區的條列不因此增減。
- `desktop-shell`：「桌面視窗形態啟動」目前承諾資料路徑不變（全部經既有本地 API），改為設定與 CLI 解析由外殼自持、其餘暫仍經本地 API；「外部指令執行通道」補上逾時上限；新增「兩種執行形態共用同一份設定」。

## Impact

- **搬移來源**：`server/utils/app-config.ts`、`server/utils/project-state.ts`、`server/utils/cli-resolver.ts`。三者的純函式部分（設定解析、解析優先序、路徑挑選）已是可注入設計，可原樣沿用；只有實際碰檔案與跑指令的部分需要換成外殼通道。
- **資料入口**：`OpenSpecGateway` 的七個方法在桌面形態改由新實作承接——`listProjects`、`addProject`、`removeProject`、`switchProject`、`getCliSettings`、`applyCliPath`、`redetectCli`。介面不變，畫面端零改動。
- **分流點**：`src/api/gateway.ts` 目前恆為 web 實作，本 change 起依執行形態分流。
- **外殼**：`src-tauri/src/lib.rs` 的執行通道加逾時；`src-tauri/capabilities/default.json` 的靜態放行範圍改指共用設定目錄。
- **過渡**：本地 API server 仍在，繼續服務尚未搬移的讀取面與檔案操作面；桌面開發通路仍併跑它。
- **可觀察的中間態**：本 change 完成後，打包的 App 側欄列得出專案、可切換、Settings 顯示得出 CLI 的偵測結果與絕對路徑，但主區 change 清單仍為錯誤狀態、「加入專案」也還按不動（選資料夾對話框尚未搬移）——這是預期結果，不是缺陷。
