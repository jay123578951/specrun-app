## 1. 外殼通道

- [x] 1.1 執行通道加逾時：`spawn_bin` 接受逾時毫秒數，改用非同步行程通道搭配逾時等待（`tokio` 的 process 與 time 兩項 feature 加為直接依賴，目前只在依賴樹裡間接存在），逾時終止該行程並回傳可辨識的逾時結果；同時接受輸出位元組上限，超過即停止累積並標記為截斷——驗收：以 `sleep 5` 搭配 1 秒上限呼叫，約 1 秒回傳逾時結果而非等滿 5 秒，且回傳後視窗仍可點選操作；以會大量輸出的指令搭配小上限呼叫，回傳帶截斷標記而非吃光記憶體
- [x] 1.2 靜態放行範圍改指共用設定目錄：`src-tauri/capabilities/default.json` 的 `fs:scope` 從外殼預設資料目錄改為 web 形態實際使用的設定目錄——驗收：前端讀得到該目錄下的 `config.json`；對該目錄以外、且未經授權通道放行的任意路徑寫入，仍被拒絕並回可辨識錯誤

## 3. CLI 解析改由前端持有

- [x] 3.1 三段降級搬到 `src/`：解析優先序、命令位置挑選、版本字串挑選為純函式，連同既有測試原樣沿用；三個 spawn 點改走執行通道並各自帶上既有上限——資料請求 15 秒、`--version` 驗證 5 秒、login shell 偵測 3 秒——驗收：既有 cli-resolver 測試在新位置全數通過

## 4. 分流與過渡

- [x] 4.1 `src/api/gateway.ts` 依執行形態分流，桌面形態走新實作、web 形態維持現狀——驗收：`pnpm dev` 開瀏覽器與 `pnpm dev:app` 開桌面視窗，兩邊的側欄清單與 Settings 內容相同
- [x] 4.2 診斷的未知態：`EnvironmentDiagnostics` 的「檔案變動通知是否運作」與「能否開啟所在位置」兩項型別放寬為可未知，桌面實作兩項都回未知，未知與明確的「是／否」在畫面上分得出來——驗收：桌面形態的 Settings 診斷區，「Live refresh」顯示「—」，其餘三行（設定檔路徑、目前專案、App 版本）有值；「能否開啟所在位置」不是診斷區的一行、而是兩顆 Show in Finder 按鈕的亮灰依據，未知時按鈕維持灰掉，滑鼠移上去的提示與「這個平台不支援」的措辭分開（2026-09-16 裁決：不為此另闢第五行，診斷區維持四行、不動 app-settings 規格）
- [x] 4.3 過渡同步：桌面形態的切換、加入、移除三個動作成功後，各額外呼叫一次本地 API server 既有的切換掛載點；呼叫失敗不讓操作失敗——驗收：桌面開發通路下切換專案，主區 change 清單跟著換到新專案（此項為過渡程式，下一張 change 收尾時刪除，已註記於 ROADMAP 的 T2 描述）

## 5. 驗收

- [x] 5.1 兩形態共用同一份設定——驗收：以 `pnpm dev` 加入一個專案，關掉後以 `pnpm dev:app` 開啟，側欄看得到該專案；反向再做一次亦然
- [x] 5.2 打包後驗證 login shell 偵測（本 change 的關鍵驗收點，開發通路驗不到）——驗收：`pnpm exec tauri build --debug` 後由 Finder 點開 `.app`，Settings 的 CLI 狀態顯示成功並帶絕對路徑；若顯示失敗，記錄失敗訊息並回報，不要就地改規格
- [x] 5.3 側欄與主區的中間態符合預期——前置：先以開發通路（`pnpm dev` 或 `pnpm dev:app`）加好至少一個專案，打包的 App 才有東西可列；驗收：打包的 App 側欄有專案、可切換，Settings 有 CLI 狀態，主區 change 清單為錯誤狀態，按「加入專案」失敗（唯一入口是尚未搬移的原生選資料夾對話框，打包形態沒有本地 API server 可問）；以上都是預期結果，不是缺陷
- [x] 5.4 跑 `pnpm lint`、`pnpm typecheck`、`pnpm test`（由 gate 覆蓋：lint／typecheck EXIT=0、vitest 30 檔 325 項、另 cargo test 14 項全過；搬移測試逐條對照未放寬——app-config 14→20、cli-resolver 13→13）——驗收：三者皆通過；搬移過來的測試若因路徑改變而失敗，調整測試的匯入路徑，不放寬既有斷言
